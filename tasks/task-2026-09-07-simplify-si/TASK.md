# Упростить исполнение задачи через /si

Objective: /si исполняет и продолжает согласованную задачу с проверяемым результатом и минимумом служебных действий в любом репозитории.
Stage / status: implementation complete / locally verified (2026-09-07).

## Контекст и решения

- Пользователь просит тот же критический аудит и упрощение, что для /ct; сохраняется указание публиковать актуальные изменения в main.
- Canonical source: alexandrbasis/claudops, baseline `d7285eb`. Приложенный .agents/skills/si — прежняя версия; исходный основной /si в main занимал 97 строк.
- Сохранены task-first, активная фаза, вертикальный TDD для изменений поведения, чужие изменения, реальные blockers, проверяемые результаты и границы разрешённых действий.

## Аудит и изменения

[Основной /si](../../.claude/skills/si/SKILL.md) сводит исполнение к четырём шагам: прочитать активную задачу и код → реализовать проверяемыми частями → проверить весь результат → сохранить статус и передать дальше. Короткий task record достаточен; подтверждения уже разрешённого действия не запрашиваются повторно.

Два справочника сокращены со 123 до 46 строк. Убраны обязательный VC-каталог, отдельный журнал мелких решений, устаревшие номера этапов и требования к конкретному async-синтаксису. Проверяется обещанный результат в API, данных, событиях или UI, включая отсутствие после удаления; наличие строки в коде не доказывает поведение.

Прямые потребители developer-agent и parallelization принимают обычное описание work item, необязательный контекстный файл и возможности текущего хоста. Передача результата должна учитывать новые, staged и закоммиченные файлы, удаления, binary и права/ссылки; изменения общего checkout проверяются на месте. TDD сохраняется для поведения; документы и форматирование проходят подходящую проверку. В TDD уточнено повторное использование текущего разрешённого scope.

## Поведенческая проверка и ограничения

В изолированном monorepo агент реализовал только выбранную фазу, сообщил RED → GREEN и сохранил чужой dirty-файл. Независимый повтор команды подтвердил 3 проходящих теста. Прогон выявил потерю ссылки на завершённую фазу при обновлении родителя; правило сохранения ссылок и разделения выбранной/ожидающей работы уточнено в /si и проверено статически, без повторного полного запуска. [Фактический diff](verification/resume-output.diff) сохраняет наблюдённый результат, включая этот недостаток.

Сценарий изменения документации остановлен до записи: автоматическая проверка разрешений назвала временный синтетический репозиторий несвязанным с запросом. После отклонённой повторной попытки через другой инструмент дальнейшие попытки прекращены. Все исходные hashes совпали; успешное выполнение этого сценария не заявляется. [Причины отказов](verification/docs-exercise-blocked.txt).

Общий Codex quick_validate отклонил существующее source-поле argument-hint, поддерживаемое форматом этого репозитория; поле сохранено. Проверки обоих пакетов используют валидатор проекта. [Точный вывод](verification/generic-validator.txt).
